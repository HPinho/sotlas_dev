# Native match guards

The Sotlas-written compiler accepts Boolean guards on scalar, Boolean,
scalar-enum, bounded integer-range and wildcard match patterns:

```sotlas
fn dispatch(opcode: u8, enabled: bool) -> u32 {
    match opcode {
        32..=47 if enabled => return 42;
        32..=47 => return 1;
        _ => return 0;
    }
}
```

## Execution contract

The selector is evaluated once. A guard is evaluated only after its pattern
matches. A true guard selects that body; a false guard tries the next arm.
Guards support the existing Boolean expression profile, including comparisons,
calls, negation and lazy `&&`/`||`. Function calls may perform the side effects
already accepted by the native profile. This does not add general effect
inference or arbitrary foreign calls.

Earlier guarded cases may overlap later explicit cases. An earlier unguarded
explicit case still rejects overlapping explicit patterns, preserving existing
duplicate/range rejection. A guarded wildcard may precede other arms. An
unguarded wildcard must remain last.

The final arm must be unguarded. Coverage is proved using only unguarded cases;
even a literal `if true` is not counted as coverage. A final wildcard or the
existing complete integer/Boolean/enum coverage proof is required.

The existing 64-arm bound applies. Guards do not introduce pattern bindings,
enum payloads or match expressions. Reference C11/LLVM parity is not claimed.

## Ownership and cleanup

Guards may read or borrow live owners through the supported POD/readonly borrow
profile. They must preserve ownership state: a guard which may consume an owner
is rejected because the false edge proceeds to another arm. Existing literal
short-circuit analysis can prove that a skipped operand never transfers its
owner. Use-after-move remains an error in guards as well as in bodies.

Ownership merges use the supported selected-body paths. Local scopes, returning
paths, loop break/continue and LIFO defer cleanup retain their existing rules.
Variables declared inside a body are not visible in its guard. This does not
provide general lifetimes, automatic ARC or resource-bearing payload ownership.

## Native implementation

The parser records the guard as the optional third child of `MatchArm`; the
pattern and body retain their existing child positions. Ownership analysis
checks the guard before the body. Lowering emits separate pattern, guard and
body CFG paths, reusing the existing short-circuit lowering and machine backend.
The three platform drivers report located guard/type/ownership failures.

The platform CLI option dispatcher also reuses repeated project-option tests.
This keeps the changed compiler inside the existing seed's string-symbol bound;
the seed's function bound is preserved without adding another branch helper.
No capacity check was removed or increased for this cut.

## Verification

The fixtures live in `tests/native/match_guards/`. The existing
`tests/native/match_ranges/cases.txt` includes them, so the platform Stage 3 gates
reuse one compiler rebuild for both features. The shared runners check located
diagnostics, check/compile rejection parity and preservation of an existing
executable after rejection. Native invocations have host tools absent from PATH.

```powershell
.\tests\native\match_ranges\verify.ps1 .\build\native-check\sotlas-native.exe .\build\match-checks
```

```bash
bash tests/native/match_ranges/verify.sh ./build/native-check/sotlas-native ./build/match-checks
```

`examples/native_guarded_dispatch.sotlas` is a complete command-dispatch example;
compile it with the native driver. Successful execution returns 42.

Local evidence (2026-10-16): all 24 shared cases (13 range and 11 guard cases)
passed on Windows x64 and Linux x86-64 through WSL. Native seeds rebuilt Stage 2
and Stage 3 with byte identity on both platforms. The command dispatcher example
returned 42 on both. The changed project-option dispatch passed info, stamp,
verification and comparison checks on Windows. The 16 documentation/reality
gates passed. The Intel macOS compiler was cross-generated by the native Windows
compiler. Full suites and Intel macOS execution were not run locally.
